# OIL India SIF Precursor Detection — Prototype

AI/NLP engine that classifies UA/UC and near-miss reports as SIF-potential
vs non-SIF-potential, tags them to the relevant IOGP Life-Saving Rule, and
surfaces recurring precursor patterns via a dashboard.

## Setup

```bash
pip install -r requirements.txt
```

First run of the model will download the `all-MiniLM-L6-v2` embedding
model (~90MB) from Hugging Face and cache it locally. Run once on a
working connection before demo day, then verify it still works with
wifi off (the model loads from cache after the first download).

## 1. Train the SIF classifier

```bash
cd src
python train_sif_model.py
```

Reads `data/final_sif.csv`, trains the MiniLM + TF-IDF + XGBoost hybrid
classifier, runs 5-fold cross-validation, and saves:
- `models/xgboost_sif_model.json`
- `models/tfidf_vectorizer.pkl`

## 2. Train the Life-Saving Rule tagger

```bash
cd src
python rule_tagger.py
```

Trains the ML backup component of the hybrid rule tagger (the keyword
layer needs no training) and saves `models/xgboost_sif_model_weighted_rule_ml.pkl`.
Prints validation accuracy and a few example taggings.

## 3. Test the combined pipeline

```bash
cd src
python pipeline.py
```

Runs a few demo reports through the full three-stage pipeline (SIF
classification + rule tagging + precursor entity extraction) and prints
the structured output, including activity, location, and barrier-failure
fields.

Requires the spaCy English model — run once before this step:
```bash
python -m spacy download en_core_web_sm
```

## 4. Launch the dashboard

```bash
streamlit run dashboard/app.py
```

Run this from the project root (`OIL-INDIA/`), not from inside `dashboard/`,
so the relative import paths resolve correctly.

The dashboard works with a small built-in demo set out of the box. To
analyze your own reports, upload a CSV with a `report` column (and
optionally a `site` column to enable the hotspot ranking view).

## Known limitations (worth stating plainly in your presentation)

- The SIF classifier reliably catches direct hazard exposure (person under
  a suspended load, unisolated live equipment, unpermitted confined space
  entry). It is less reliable on the distinction between "hazard present
  nearby" and "hazard present but actively being worked on under proper
  control" — this is the hardest distinction in the SIF framework and
  would benefit most from more real OIL report data.
- The Life-Saving Rule tagger uses keyword matching as its primary signal
  because it is more explainable and generalizes better to real-world
  phrasing than a small ML model trained alone (verified during
  development — a pure ML tagger trained on ~150 rows returned zero
  matches on real OSHA incident narratives).
- Trained on ~390 examples combining hand-written synthetic reports and a
  cleaned real-incident-style dataset — not OIL's actual HSSE data, since
  none was provided with the problem statement.
